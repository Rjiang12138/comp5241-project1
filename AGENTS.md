# Notes for whoever edits this next — human or agent

Short on purpose. Everything here is a rule the code depends on, or a trap that
has already cost time once. If you are an AI agent, read this file before your
first edit and re-read §3 before you claim something works.

## 1. What this is

Praxis: a Next.js 15 (App Router) + Prisma + Postgres app that turns lecture
material into short courses. One instructor generates a course, learners play it,
every click appends to an `events` table, and every number on screen is a query
over that table.

```bash
npm install            # also runs prisma generate
npm run db:push        # apply prisma/schema.prisma
npm run db:seed        # load the fixture — TRUNCATES, see §3
npm run dev            # http://localhost:3000
npm run typecheck      # tsc --noEmit
npm run build          # prisma generate && next build — this is what CI runs
```

Environment: `DATABASE_URL` and `DATABASE_URL_UNPOOLED` are required;
`CHATANYWHERE_API_KEY` / `OPENROUTER_API_KEY` are optional and the app is
designed to work without them. `.env.local` is gitignored. Never print a key,
never commit one, never paste one into an issue or a transcript.

## 3. Rules the code depends on

1. **Progress is a query, never a column.** Do not add `completed` or `progress`
   to a table. `activity_completed` rows in `events` are the truth; `/path`,
   `/insights`, the course editor and the learner shelf all derive from them.
   Two sources of truth is how the 40% bug in `docs/test-plan.md` §8.12 happened.

2. **Writes go through `lib/store.ts`.** A component or a page must not import
   `prisma` directly. The one exception is `app/learn/actions.ts`, which reads an
   enrolment to verify ownership before writing an event.

3. **Every page that draws a person calls `requireUser` / `requireStaff` /
   `requireRole`.** Not the sidebar — the sidebar only hides links. The server
   check is the control.

4. **`contentFor()` order is load-bearing:** hand-written text → `Activity.payload`
   → `fallback()`. Do not reorder, and do not write a `payload` onto an activity
   that has hand-written text — it would be shadowed and the screen would look
   unchanged.

5. **Never run `db:seed` or `db:reset` against a database you do not own.** Both
   truncate every table the fixture owns, including courses someone generated by
   hand. The shared Neon branch is not yours.

6. **Model calls only through `completeJson()` in `lib/llm.ts`.** It owns the
   queue, the minimum gap, the `Retry-After` handling and the attempt budget.
   Calling `fetch` against a provider from anywhere else skips all four and is
   how a free key gets banned.

7. **One design system.** `app/globals.css` only. There is no second stylesheet,
   no Tailwind, and no generated component to keep in step.

8. **Navigation happens on the server.** A server action that should move the
   learner calls `redirect()`. A client `router.push()` followed by
   `router.refresh()` in the same tick loses the race and leaves the learner on
   the activity they just finished (D-18).

## 4. Traps

- **`maxDuration = 60` is declared on `/studio` and `/path`.** A generation takes
  ~14 s; serverless defaults to 10 s. Removing that export breaks production only.
- **The throttle is per process.** On serverless, two concurrent visitors are two
  instances. The queue cannot be global without a database lock.
- **PDF parsing and Prisma need the Node runtime.** Do not mark these routes
  `runtime = "edge"`.
- **`DATABASE_URL_UNPOOLED` is for DDL.** `db:push` fails against the pooler.
- **Seed ids are load-bearing.** `e-1…e-24` are referenced by the fixture event
  log; new enrolments use `e-<n>-<courseId>` for that reason.
- **`prototype/` is a design reference.** Nothing renders from it. Do not
  reintroduce a converter or a second copy of the CSS.

## 5. How to say it works

There is no automated end-to-end suite. Before you report a change as working:

1. `npm run typecheck` — silent is passing.
2. `npm run build` — must complete.
3. Click the flow you changed, or `curl` the route with a session cookie
   (`praxis_uid=u-kwok` is an instructor, `u-tse` is the admin, `u-arjun` is a
   learner at 6/7 on `c-sef`).
4. State what you actually ran. "Should work" is not a result, and this repository
   has a 23-row defect log made almost entirely of things that looked fine.

If you write a defect up, follow the shape in `docs/test-plan.md` §8: what was
observed, what the cause was, and a before/after table. That document is the
institutional memory here.

## 6. Style

- Prose is English. Comments explain *why*, not what — if a line needs a comment
  to say what it does, rename something instead.
- Commit messages have a subject in the imperative and a body that says what was
  wrong before. Look at `git log` — that is the house style.
- Do not add a dependency for something thirty lines can do. The list is short on
  purpose.
