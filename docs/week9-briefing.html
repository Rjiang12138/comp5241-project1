1. Where we are

The mid-term prototype was six static screens. Since then the platform behind them has been built: a Next.js application, a Postgres database, a session with role guards, and server actions that make the instructor screens write to it. The screens themselves are unchanged — the prototype is the source of truth for the interface, and every screen in the app is generated from it by a converter rather than re-typed.

2. System design

browser ──form POST──▶ server action ──▶ lib/store.ts ──▶ Prisma ──▶ Neon Postgres
                            │
                            └── revalidatePath ──▶ the same page re-renders

No hand-written API layer. Every mutation is a server action. The form posts, the action validates, the store writes, the page re-renders. There is no REST endpoint to keep in sync with the UI and no client-side fetch for course data, so a screen cannot drift out of step with the schema it writes to.

The prototype owns the interface. tools/html_to_tsx.py converts prototype/*.html into the React components under components/ported/. Behaviour is added around the markup, not inside it. This is why the app looks exactly like the artefact reviewed in week 7, and why a design change is a one-line edit in one file followed by a re-run, not a sweep through six screens.

Ten tables, one writer. users, cohorts, courses, modules, activities, enrollments, events, course_versions, ai_runs, prompt_versions. lib/store.ts is the only module that writes; pages read through it. The unique (courseId, position) constraint on modules is why reordering and deletion need renumbering, and that logic lives in one place because of it.

5. What we are not claiming

  • Three surfaces write to the database, four do not. The course editor, the cohort registry and settings are live. The studio form, the learner player, the path builder and the analytics page are still prototype markup. We will demo the first three and describe the rest as designed, not built.
  • There is no authentication. The session is a role switcher for demonstration; it is not a login. Real accounts are out of scope for week 11.
  • No AI call has been made. Every outline seen so far is fixture data. The generation step lands in week 10, and the interface will say which mode produced a course.
